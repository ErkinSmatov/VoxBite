<objective>
Build the second half of the offline FDC indexing pipeline: a shared OpenAI
embedding adapter, an idempotent Drizzle loader for `fdc_foods`, and the
`npm run index-fdc` entrypoint that wires parse → resolve → embed → upsert with
the counters and coverage stats the owner needs to trust the result.

Purpose: This is the code that turns Plan 05's clean records into the vector
index MATCH-01 queries. It is also where real money gets spent, so batching,
order preservation, resumability and re-run skipping are built in from the
first version rather than retrofitted (01-RESEARCH.md Pattern 5, threat T-01-03).

Output: Working, typechecked pipeline code. This plan does NOT run the full
index — Plan 07 does that, so a code bug is caught by tests before any bulk
billing happens.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Local indexer -> OpenAI API (HTTPS) | Every call spends the owner's prepaid balance |
| CSV-derived text -> Postgres INSERT | Untrusted-shaped strings cross into SQL |
| Partial run state -> re-run | A crashed run must not corrupt or duplicate the index |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-01-03 | Denial of Service (owner's budget) | `openai-embed.ts`, `run.ts` | mitigate | Sequential batches of 100 (no `Promise.all` burst), `insufficient_quota` never retried, cost estimate + API-call count printed before the first call, `--dry-run` and `--limit` for cheap rehearsal, and version-based skipping so a re-run does not re-embed |
| T-01-22 | Injection | `load.ts` upsert of CSV descriptions | mitigate | Drizzle query builder parameterizes every value; a static check rejects raw `INSERT INTO` strings in `load.ts` |
| T-01-23 | Tampering (index corruption) | Mixed embedding models in one HNSW index | mitigate | Every row stores `embedding_model_version` and `dataset_version`; `loadExistingVersions` compares both before skipping, so a model change forces a re-embed instead of silently mixing vector spaces |
| T-01-24 | Tampering (MATCH-02 violation) | `run.ts` | mitigate | Hard abort when the Foundation kept-count exceeds 5,000, plus the printed `88,314 → 469` line, so a regressed `data_type` filter cannot reach the database unnoticed |
| T-01-25 | Information Disclosure | Error logs from the embedder | mitigate | The adapter logs batch indexes and counts only — never the API key, never the embedded text |
</threat_model>
