<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Developer machine -> git remote | Secrets (Supabase DB password, OpenAI key) must never cross this boundary |
| Local process -> Supabase Postgres (TLS) | Credentials in transit |
| Local process -> OpenAI API (HTTPS) | API key in transit; billable calls |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-01-02 | Information Disclosure | `.env`, `.env.example`, `scripts/check-setup.ts` | mitigate | `.gitignore` ships `.env` + `.env.*` with an `!.env.example` negation in the very first commit; `.env.example` holds placeholders only; `check-setup.ts` masks credentials and never logs them |
| T-01-05 | Tampering (misconfiguration) | `src/config/env.ts` | mitigate | `dotenv-safe` validates `.env` against `.env.example` inside `loadEnv()`; missing/empty required vars fail fast with a named-key error instead of surfacing as a cryptic runtime failure |
| T-01-04 | Information Disclosure | Postgres/OpenAI TLS | mitigate | `?sslmode=require` documented in `.env.example`; no code path sets `rejectUnauthorized: false` or otherwise disables certificate handling |
| T-01-06 | Denial of Service (owner's budget) | `scripts/check-setup.ts` | accept | The check performs exactly one 4-token embedding call per invocation; cost is below $0.000001 and is stated in the script output |
</threat_model>
