<objective>
Build the data-acquisition and data-mapping half of the offline USDA FDC
indexing pipeline: download and unpack the two bulk CSV bundles, stream-parse
`food.csv` with the `data_type = 'foundation_food'` filter that MATCH-02
actually depends on, and resolve per-100g nutrients through a priority-ordered
nutrient-ID table that leaves missing values as `null`.

Purpose: 01-RESEARCH.md's single most important finding is that Foundation
Foods' `food.csv` is 88,314 rows of which only 469 (0.53%) are real foundation
foods — the rest are lab samples and brand-named retail purchases like
"HUMMUS, SABRA CLASSIC". Indexing them would violate MATCH-02's intent without
ever touching the Branded Foods dataset. The second finding is that a single
hardcoded nutrient ID per macro silently produces null calories for 71% of
Foundation Foods records. Both are pure data-mapping bugs no library can catch,
so both get explicit unit tests here, before any embedding money is spent.

Output: Tested, DB-free, OpenAI-free modules that turn two CSV bundles into
clean `{ fdcId, description, source, kcal, proteinG, fatG, carbsG, sugarG }`
records. Plan 06 embeds and loads them.
</objective>
