  <action>
    Create `scripts/index-fdc/verify-index.ts`, run via the existing
    `npm run verify-index` script. It reads `fdc_foods` and asserts, printing a
    labelled `[ok]`/`[FAIL]` line with a plain-language explanation for each:

    1. Row count is within 7,900-8,400. Below the band means a partial load
       (remedy: re-run `npm run index-fdc`); far above means the Foundation
       `data_type` filter regressed (remedy: 01-RESEARCH.md Pattern 2).
    2. `select source, count(*) group by source` returns exactly the two allowed
       values, with `foundation_food` between 380 and 500 and `sr_legacy_food`
       between 7,500 and 7,900. FAIL on any third source value, naming it.
    3. Brand-pollution probe: `select count(*) where description ilike '%sabra%'
       or description ilike '%kellogg%' or description ilike '%nestle%'
       or description ilike '%, brand%'` returns 0. Print the matched
       descriptions on failure. This is the human-legible MATCH-02 assertion —
       it catches the failure mode where the filter silently stopped working.
    4. Embedding integrity: `select count(*) where embedding is null` is 0, and
       `select min(vector_dims(embedding)), max(vector_dims(embedding))` both
       equal 1536.
    5. Nutrient coverage: compute the non-null percentage for `kcal`,
       `protein_g`, `fat_g`, `carbs_g`, `sugar_g` overall AND grouped by
       `source`, and print them as a table. Assert `protein_g` coverage > 90%
       overall (a collapse means nutrient-ID resolution broke) and assert
       `sugar_g` coverage is strictly between 0% and 100% — 0% means resolution
       broke, 100% means somebody coalesced missing sugar to a value, and both
       are bugs. Print the reminder that a NULL sugar is correct and will be
       displayed as "нет данных".
    6. Zero-vs-null sanity: assert `select count(*) where sugar_g = 0` is small
       relative to the NULL count, and print both numbers side by side so a
       future regression that turns NULLs into zeros is immediately visible.
    7. Version stamping: `select distinct dataset_version, embedding_model_version`
       returns only expected pairs (`2026-04-30`/`text-embedding-3-small` and
       `2018-04`/`text-embedding-3-small`). More than one embedding model in the
       table is a FAIL — mixed vector spaces in one HNSW index make similarity
       meaningless.
    8. Spot-check sample: print 5 random rows (fdc_id, source, description,
       kcal, sugar_g rendered as `нет данных` when NULL) so the owner can eyeball
       real data without opening the Supabase dashboard.

    Support `--json`. Close the connection in a `finally`. Print `INDEX OK` and
    exit 0 when all checks pass; otherwise print a numbered remediation list and
    exit 1.
  </action>
