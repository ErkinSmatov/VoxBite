| Boundary | Description |
|----------|-------------|
| owner's local filesystem → this process | `samples/voice/*` files are owner-supplied audio read by `verify-stt`; they are personal health-adjacent data and are gitignored |
| this process → api.openai.com | audio bytes leave the machine over TLS; the API key crosses this boundary |
| runtime audio Buffer → logs/disk | the only place raw audio could leak (D-05) |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-03-01 | Information Disclosure | `src/adapters/stt/openai-transcribe.ts` | mitigate | Buffer handed to `toFile()` in memory only; grep gate in acceptance criteria proves no `writeFile`/`createWriteStream` in `src/adapters/stt/`; module doc comment forbids logging the key, audio or transcript |
| T-03-02 | Information Disclosure | `samples/voice/` | mitigate | `samples/` added to `.gitignore` and asserted by `git status --porcelain samples` being empty, so the owner's voice never reaches the remote repo |
| T-03-03 | Denial of Service (financial) | `scripts/verify-stt.ts` | mitigate | Pre-flight line prints file count and total estimated cost before any paid call; script transcribes only files already on disk (bounded set), never loops |

| T-03-05 | Spoofing | OpenAI credentials | accept | Key handled exclusively by the existing `loadEnv()` path from Phase 1; no new key material, no new storage location — already covered by ASVS V6 assessment in 03-RESEARCH.md |
