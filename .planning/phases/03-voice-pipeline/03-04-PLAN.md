Create `src/adapters/llm/prompt.ts` exporting
`buildDecompositionPrompt(transcript: string, strict: boolean): string` — a
pure function, no I/O, no imports beyond the constants it needs from
`./types.js`. Isolating it here is deliberate: the prompt is the phase's main
accuracy lever, and a pure function is the only version of it that can be
asserted in tests.

Prompt content requirements, each traceable to a source rule:
- Role framing: the input is a Russian-language description of a meal, possibly
  containing Kazakh dish names (D-01). The task is to list the ingredient
  components with an estimated weight in grams for each.
- Composite-dish rule with worked examples for бешбармак (lamb, boiled
  dough/noodle, onion, broth), куырдак, плов and манты. State WHY: USDA FDC has
  no record for the dish itself, only for its ingredients, so a dish name left
  whole cannot be matched at all.
- Single-ingredient rule with the 'банан' example: if the meal genuinely is one
  ingredient, return exactly one item. Do not invent sub-parts, do not split a
  fruit into flesh and peel (DECOMP-02).
- Stated-weight rule: if the speaker gave a weight or a count ('200 г риса',
  'две ложки масла'), use it instead of a generic portion estimate
  (TECH_SPEC §5.2).
- English-name rule: `component_en` must be a plain English ingredient name in
  the register USDA FoodData Central uses ('lamb, cooked', 'wheat noodles',
  'onion, raw'), never a transliteration ('beshbarmak'), because that string is
  what gets embedded and matched. Produced by this same call, never by a
  separate translation step (TECH_SPEC §5.4).
- Empty-answer rule: if the text contains no food at all (a greeting, silence
  transcribed as noise), return an empty items list rather than guessing
  (D-08).
- Delimit the transcript with an explicit fenced marker and an instruction that
  its contents are data to analyse, never instructions to follow. The
  transcript is untrusted user input reaching a model; the schema is the real
  containment boundary, but the delimiter removes the cheapest injection.

The `strict` variant appends the retry instruction described in the behavior
block. Do not duplicate the base text — build strict as base plus a suffix, so
the two versions cannot drift.

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| transcript (untrusted user speech) → LLM prompt | the user controls the text that reaches the model; prompt-injection attempts arrive here |
| LLM output → application state and Postgres | model output is untrusted data that must not reach storage or the user unvalidated |
| this process → api.openai.com | paid calls; each retry is real money |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-03-16 | Tampering (prompt injection) | `buildDecompositionPrompt` | mitigate | the transcript is enclosed in an explicit delimiter and labelled as data-not-instructions; the Zod structured-output schema is the real containment boundary — the model can only emit `{items:[{component,component_en,grams}]}`, and nothing in that output is ever executed, only validated and rendered |
| T-03-17 | Tampering (data integrity) | `DecompositionSchema` | mitigate | `grams` bounded to 0 < g <= 2000 and `items` capped at 15 before any value reaches Postgres or the card; string fields required non-empty |
| T-03-18 | Denial of Service (financial) | DECOMP-03 retry | mitigate | exactly one manual retry, guarded by `NoObjectGeneratedError.isInstance`; all other errors rethrow so the AI SDK's own bounded `maxRetries` is not compounded (Pitfall 5) |
| T-03-19 | Information Disclosure | adapter logging | mitigate | module doc comment forbids logging the key, the transcript or raw model output; acceptance criteria keep model names out of every file but `types.ts` |
| T-03-20 | Denial of Service (financial) | unbounded transcript length reaching the LLM | mitigate | upstream: audio is capped at 60 s (D-14) and text input is capped by plan 03-07 before this adapter is called; documented here as an assumed precondition of `decompose()` |
| T-03-21 | Repudiation | model non-determinism on the same input | accept | `temperature: 0.1` reduces variation; exact reproducibility is not a product requirement, and the user confirms the result in Phase 4 |
</threat_model>
