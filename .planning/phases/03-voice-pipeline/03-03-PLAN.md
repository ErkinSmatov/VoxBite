<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| LLM output / FDC description → rendered Telegram message | untrusted or third-party text is interpolated into a message shown to the user |
| draft data → user-visible text | the card must not disclose more than intended (no internal error strings, no scores) |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-03-12 | Tampering (rendering injection) | `buildResultCard` interpolating LLM-authored `component` text and FDC `description` | mitigate | the card is sent as plain text with no `parse_mode`, so Telegram markup metacharacters in model or FDC output cannot alter rendering; documented in the module doc comment and relied on by plan 03-07 |
| T-03-13 | Information Disclosure | error copy in `pipeline-copy.ts` | mitigate | every failure string is a fixed constant; no interface accepts an error object or interpolates an exception message, so an internal detail cannot reach the user (matches `error-copy.ts`'s existing rule) |
| T-03-14 | Repudiation / integrity of displayed data | weak-match handling | mitigate | `isWeakMatch` is a single exported pure function used by both the pipeline and the card, so the flag shown to the user cannot drift from the flag stored in the draft |
| T-03-15 | Information Disclosure | similarity scores and runner-up candidates | accept | deliberately not rendered (D-18); no security impact, recorded here because the draft row does retain them for Phase 4 |
</threat_model>
