    there is nothing to swap to.

  <action>
    Props: `{ draftId, componentIndex, grams, onUpdated(next), onError(message) }`.

    Layout: a horizontal row of three controls, each `.tap-target` —
    `copy.btnMinus10`, the grams value, `copy.btnPlus10`.

    The two stepper buttons POST to `/api/drafts/${draftId}/adjust-grams` with
    `{ componentIndex, direction: 'down' | 'up' }`. They send a direction, never a number —
    the ±10 step is a server-side product rule (see plan 05). Do not disable them at the
    boundaries; the server clamps and returns unchanged grams, which is the intended visible no-op.

    Tapping the grams value switches it to a controlled `<input>` with `inputMode="numeric"`
    (so Telegram's WebView shows a numeric keypad) and autofocus. On submit (Enter or blur), POST
    the raw string to `/api/drafts/${draftId}/typed-grams` as `{ componentIndex, raw }`.
    Send the string EXACTLY as typed — do not trim, strip a `г` suffix, replace a comma with a dot,
    round, or bounds-check it in React. `parseGrams` on the server is the single parser for this
    value across the whole product, and a client-side pre-parse is precisely the kind of second
    implementation that drifts. Escape reverts to display mode without a request.

    A 422 `invalid_grams` response renders `copy.gramsRejected` inline directly beneath this
    control and keeps the input open with the text still in it — never a toast, never an
    `alert()`, never a full-screen error. Any other failure calls `onError(copy.saveFailed)`.

    While a request is in flight, disable all three controls and show a subtle busy indication;
    on success call `onUpdated(data)` and return to display mode.

    Render `grams` exactly as the API returned it. No unit conversion, no rounding — the server
    already stores an integer gram value.
  </action>

| T-04.1-41 | Information Disclosure | showing the wrong food for a corrupt row | mitigate | `ComponentRow` renders `copy.noMatch` when the chosen id is absent from the candidates array rather than falling back to `candidates[0]` — an honest gap beats a confident wrong number (Core Value) |

| T-04.1-43 | Repudiation | a failed mutation silently ignored | mitigate | Every failure path renders either the inline `gramsRejected` message or a screen-level error banner; there is no silent catch |
