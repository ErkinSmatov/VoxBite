# Phase 04.1 Plan 09: Component List — Candidate Picker, Grams Control, Component Row Summary

**Built the three interactive controls that replace the retired `crc:` chat keyboards: an inline (non-modal) accordion for swapping a component's matched FDC record, a ±10 g stepper with a tap-to-edit exact-value numeric input, and the row that composes both plus the remove action — every mutation re-renders the whole screen from the server's `DraftResponse`, never a local guess.**

## Tasks Completed

### Task 1: CandidatePicker
- File: `mini-app/src/components/CandidatePicker.tsx`
- Collapsed state shows the `Сменить вариант` affordance; expanded state is an inline accordion
  (no `<dialog>`, no `<select>`, no `window.confirm`/`alert`) listing candidates in API order,
  each row showing `candidate.description` and the accent-colored `✓` beside the chosen one.
- Tapping the already-chosen candidate just collapses (no request). Tapping a different one POSTs
  `{ componentIndex, candidateIndex }` to `/api/drafts/:id/swap-candidate`; on success calls
  `onUpdated(data)` and collapses; on failure calls `onError(copy.saveFailed)` and stays open.
- Empty `candidates` renders `copy.noMatch` as static caption text with no affordance.
- Commit: `70e600f`

### Task 2: GramsControl
- File: `mini-app/src/components/GramsControl.tsx`
- `−10 г` / grams value / `+10 г`, all `.tap-target`. Steppers POST `{ componentIndex, direction }`
  to `/api/drafts/:id/adjust-grams` — never a computed delta.
- Tapping the grams value switches to a controlled `inputMode="numeric"` autofocus input; Enter or
  blur submits the raw string verbatim to `/api/drafts/:id/typed-grams`; Escape reverts without a
  request. No `parseInt`/`parseFloat`/`Number()`/`.trim()`/`.replace()`/`Math.round` in this file —
  `parseGrams` on the server is the only parser.
- A 422 `invalid_grams` response renders `copy.gramsRejected` inline beneath the control and keeps
  the typed text; any other failure calls `onError(copy.saveFailed)`.
- Commit: `55b802a`

### Task 3: ComponentRow + App.tsx wiring
- Files: `mini-app/src/components/ComponentRow.tsx`, `mini-app/src/App.tsx`, `mini-app/src/styles.css`
- `ComponentRow` renders the component name, the chosen candidate's description (or `copy.noMatch`
  for a null/corrupt `chosenFdcId` — never falls back to the first candidate in the list), the
  `CandidatePicker`, the `GramsControl`, and a destructive-colored `✕ Убрать` row footer that POSTs
  `{ componentIndex: index }` to `/api/drafts/:id/remove-component` with no confirmation dialog.
- `App.tsx` now maps `draft.components` to `ComponentRow` (keyed on index, since the list is
  replaced wholesale from each API response — documented inline), passes `updateFromResponse` as
  `onUpdated`, and a new `handleMutationError` as `onError` that sets a screen-level inline banner
  rather than blanking the screen. Header/footer remain plan-08 placeholders per the plan.
- Commit: `2116c5a`
