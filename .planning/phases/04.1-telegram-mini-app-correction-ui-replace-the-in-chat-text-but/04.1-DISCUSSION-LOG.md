## Технология для мини-аппа (pre-phase-insertion clarification)

| Option | Description | Selected |
|--------|-------------|----------|
| Telegram Mini App на веб-React | Web page inside Telegram's WebView, opened from the bot's menu button | ✓ |
| Отдельное React Native приложение | Native iOS/Android app — does NOT integrate with a bot menu button | |

**User's choice:** Telegram Mini App on web React.
**Notes:** The user's original phrasing ("React Native мини апп … добавлять его в бот в кнопку меню")
conflated two different technologies. Flagged the mismatch before proceeding — React Native builds
native apps and cannot be embedded via a bot's `web_app` menu button; a Telegram Mini App is a web
page and is what "opens from a bot menu button" actually means.

## Замена или дополнение существующего флоу (pre-phase-insertion clarification)

| Option | Description | Selected |

| Полная замена | Chat card + inline keyboards removed; all correction happens in the Mini App | ✓ |

**Notes:** This confirmed the scope was a genuine architecture pivot, not an additive feature —

## Хостинг

| Option | Description | Selected |
|--------|-------------|----------|
| Vercel | Static build + small API, free tier covers this scale, `git push` to deploy | ✓ |
| Та же платформа, что и хостинг бота | Single ops surface, but requires deciding bot deployment first — out of order | |

**User's choice:** Vercel.
**Notes:** The bot itself stays running locally on the owner's machine — this decision only
concerns the Mini App's static assets + API, which only need reachability to the already-cloud-
hosted Supabase Postgres instance, not to the bot process itself.

## Адресация конкретного черновика

| Option | Description | Selected |
|--------|-------------|----------|
| Кнопка на каждой карточке | Each analysis message gets its own "Open" web_app button carrying that draft's id | ✓ |
| Только глобальная кнопка меню | One bot-wide menu button with no message-specific context | |

**User's choice:** Button on each card.
**Notes:** Removes the ambiguity of "which of several open drafts does the global button mean" —
matches Phase 3's D-13 precedent of one message, extended in place, per analysis.

## Судьба чата после перехода на мини-апп

| Option | Description | Selected |
|--------|-------------|----------|
| Краткая сводка после сохранения | Bot still edits the message into a final-numbers summary after confirm | |
| Чат молчит, всё в приложении | Bot never rewrites the ack message into a card or summary — only adds the Open button | ✓ |

**User's choice:** Chat stays silent; only the ack message + Open button ever appear.
**Notes:** More radical of the two options. Creates a known, explicitly-accepted gap: without a
chat summary and without Phase 5's diary views yet built, finding a past saved entry means
scrolling chat history for its original message. Flagged directly to the user as a consequence,
not silently absorbed — recorded under Deferred in CONTEXT.md as a hard requirement for Phase 5.
