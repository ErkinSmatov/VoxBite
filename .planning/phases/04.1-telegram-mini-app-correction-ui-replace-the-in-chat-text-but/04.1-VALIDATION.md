## Test Infrastructure

| Property | Value |
|----------|-------|
| **Framework** | Vitest 4.1.10 (already the project's test runner) |
| **Config file** | none dedicated — project relies on Vitest defaults (`npm test` → `vitest run`) |
| **Quick run command** | `npx vitest run src/application/corrections.test.ts src/application/draft-store.test.ts src/application/confirm-meal.test.ts` (and the new `api/**/*.test.ts` once added) |
| **Full suite command** | `npm test` |
| **Estimated runtime** | ~10-20 seconds |

---

## Sampling Rate

- **After every task commit:** Run the quick run command, scoped to the file(s) touched.
- **After every plan wave:** Run `npm test` (full suite).
- **Before `/gsd:verify-work`:** Full suite must be green, PLUS a manual owner-executed checklist for the actual Mini App UI inside a real Telegram WebView (no way to script a real Telegram WebView session — same precedent as Phase 4).
- **Max feedback latency:** ~20 seconds.
