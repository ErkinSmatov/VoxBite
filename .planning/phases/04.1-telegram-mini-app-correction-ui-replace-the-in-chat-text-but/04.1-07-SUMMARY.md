## Accomplishments

- `api/drafts/[id]/recompute.ts` -- the CORRECT-08 explicit `Сохранить изменения` action. Calls `recomputeSavedEntry` exactly once with no request body read; maps `ok: true` to a fresh `DraftResponse` (re-read from `readDraft`), `not_saved` to 409, `blocked` to 422 with the `blockedComponent` name, `not_found` to 404. Greps clean of any date-computation token (D-07): the response's `localDate` is whatever the re-read draft already has, never derived here.
- `api/drafts/[id]/delete.ts` -- permanent delete (D-08) behind `z.literal(true)`, not `z.boolean()`, so `{confirmed: false}` and a string `'true'` both fail validation before `deleteSavedEntry` is ever reached. `already_deleted` maps to an idempotent 200 `{deleted: true}` (checked BEFORE any error-status logic, per the plan, so a double-tap is never an error). Response body is exactly `{deleted: true}` -- verified by a dedicated test asserting the JSON body has no other keys.
- `api/drafts/[id]/cancel.ts` -- the D-12 empty-state escape hatch. Reads no request body; `claimAbandon`'s `fromStatus` argument is the hardcoded literal `'draft'` written directly in the file. Both a won and a lost claim race return an identical 200 `{cancelled: true}` so the response can never leak whether the draft existed or was already in another state.
- `api/drafts/__tests__/recompute-guard.test.ts` -- one table-driven test enumerating all five mutation endpoint factories (`swap-candidate`, `adjust-grams`, `typed-grams`, `remove-component`, `add-component`), each paired with a minimal valid body and a fake application function returning `{ok: true, components: [...]}`. Asserts `recomputeSavedEntry` is called exactly once with `(db, draftId, userId)` when the draft is confirmed, and zero times when it is a plain draft -- for every one of the five endpoints. A filesystem-derived count assertion (`readdirSync` over `api/drafts/[id]`, minus the four known non-mutating endpoint filenames) fails if a sixth mutation endpoint is ever added without a matching table row.

## Decisions Made

### `delete.ts` passes the literal `true`, and omits `now`, in its `deleteSavedEntry` call

The plan's `<behavior>` bullet reads: `{ confirmed: true } -> deleteSavedEntry(db, draftId, user.id, true) called exactly once`. `confirm-meal.ts`'s real signature is `deleteSavedEntry(db, draftId, userId, confirmed, _now?)`, with `_now` explicitly documented as unused (same as `recomputeSavedEntry`'s own `_now`). The acceptance criterion greps for `deleteSavedEntry\([^)]*,\s*true\s*\)` -- a pattern that only matches when `true` is the LAST token before the closing paren, i.e. a call with no trailing `now` argument. Both the plan's stated behavior and the grep converge on a bare four-argument call, `deleteSavedEntry(db, draftId, user.id, true)`, with no `d.now()` passed. The handler still accepts an injectable `now` dependency for interface parity with the other endpoints (and so a future call site that DOES need a fixed clock for a test has the seam already in place), it just isn't threaded into this particular call.

### `recompute-guard.test.ts`'s mock-to-real-signature casts are confined to the test file

Five mutation endpoints have three structurally different dependency shapes (`swapCandidate(db, id, userId, componentIndex, candidateIndex, now?)`, `removeComponent(db, id, userId, componentIndex)`, `addComponent(db, id, userId, raw, {embedder, repo})`). A single shared `HandlerBuild` interface with one untyped `ReturnType<typeof vi.fn>` per role (`appFn`/`readDraft`/`recomputeSavedEntry`), cast `as never` only at the point each table entry hands it to its own `createXHandler`, keeps the table itself uniform (one row per endpoint, same three fields) without either duplicating the table five times with five different generic type parameters, or loosening any type in the production endpoint files -- `npx tsc --noEmit` passes clean with zero `as never`/`as any` anywhere outside this one test file.
