<objective>
Replace the step where the voice pipeline rewrites its ack message into a Phase-4 correction card
with a step that leaves the message as a short status line and attaches a Telegram `web_app`
button pointing at the Mini App, addressed to that specific draft (D-02, D-03).

Purpose: this is the only thing that makes the Mini App reachable at all. Everything else in this
phase is unreachable code until this button exists in a real chat message.
Output: a new `OpenCorrectionRenderer` port + its grammY implementation, a required
`MINI_APP_BASE_URL` env var, and a rewritten reachability tripwire that fails if the button ever
stops being emitted.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| bot process -> Telegram chat | Anything written into a chat message is health data leaving the system |
| `.env` -> `web_app.url` | An operator-supplied string becomes a URL Telegram will open |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-04.1-03 | Information Disclosure | ack message text | mitigate | `OpenCorrectionRenderer.renderOpenButton(draftId)` is given only a number — it structurally cannot render component/nutrient text; task 3's tripwire asserts the emitted text contains no fixture component names or numbers (D-03) |
| T-04.1-04 | Tampering | `MINI_APP_BASE_URL` | accept | The value is operator-controlled configuration in `.env`, not user input; a wrong value produces a broken button, not a privilege escalation. Documented shape (`https://…`, no trailing slash) in `.env.example`; trailing slashes stripped defensively |
| T-04.1-05 | Denial of Service | missing `MINI_APP_BASE_URL` | mitigate | Added to `REQUIRED_ENV_KEYS` so the bot fails loudly at startup rather than shipping messages with no reachable correction path |
| T-04.1-06 | Spoofing | draft id in a public URL | accept | The draft id in the URL is not an authorisation token — every `/api` call independently validates `initData` and every application-layer call is scoped by `(draftId, userId)`. Knowing another user's draft id grants nothing (plan 03 enforces this) |
</threat_model>
