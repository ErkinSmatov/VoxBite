## Decisions Made

- **Extensionless-import convention reversed.** 04.1-03-PLAN.md had locked a rule that relative imports under `api/**` should NOT carry a `.js` extension, reasoned from how esbuild (Vercel's build step) and Vitest's esbuild transform resolve imports. That reasoning didn't account for Vercel's deployed Function runtime, which executes the already-compiled `.js` output directly through Node's native ESM loader — and that loader requires explicit extensions on relative specifiers. Confirmed via two separate live `ERR_MODULE_NOT_FOUND` production crashes (see below). Every relative import in `src/**` and `api/**` now carries an explicit `.js` extension; both prior plan docs are annotated SUPERSEDED so no future plan reintroduces the broken pattern.
- **Fixed repo-wide in one pass, not module-by-module.** After the first fix (scoped to non-test files directly under `api/`) resolved one crash but immediately surfaced a second `ERR_MODULE_NOT_FOUND` in `src/db/schema/index.ts` (proving `src/**` was NOT already `.js`-suffixed as 04.1-03-PLAN.md assumed), the second fix swept all of `src/**/*.ts` and `api/**/*.ts` including test files in one pass, then grepped for zero remaining extensionless relative imports — avoiding a third redeploy-log-relay round trip.
- **Stale `origin/main` fixed with a plain `git push`, not a rewrite.** GitHub was 342 commits behind local `main` (commit `51b50a4`, predating `vercel.json`/`api/`/`mini-app/` entirely) — the entirety of phase 04.1 had never been pushed. Confirmed clean fast-forward (no divergent history) before pushing.
- **CORS left unchanged.** `curl -H 'Origin: https://example.com'` against `/api/drafts/1` returns no `Access-Control-Allow-Origin` header at all — already restrictive/absent, matching RESEARCH.md's Security Domain note that the initData HMAC signature is the real access control, not CORS. No `vercel.json` header change made.

## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 1 - Bug] `origin/main` on GitHub was 342 commits behind local `main`**
- **Found during:** Task 2, investigating the first-deploy 404 (`x-vercel-error: NOT_FOUND` on every path, including `/api/*`)
- **Issue:** Vercel's build log showed it cloned commit `51b50a4` — a Phase 1 commit predating `vercel.json`, `api/`, and `mini-app/` entirely. The whole `04.1` phase existed only on the local machine; it had never been `git push`ed.
- **Fix:** Confirmed a clean fast-forward (no divergent history), ran `git push origin main` from the main checkout (not this worktree) with explicit owner approval, landing `51b50a4..4709cae`.
- **Files modified:** none (push only)
- **Verification:** Vercel auto-deployed the new push; subsequent curl to `/` returned `200` with the correct Mini App HTML instead of `404`.
- **Committed in:** n/a (push, not a commit in this worktree)

**2. [Rule 1 - Bug] `api/**` and `src/**` relative imports lacked the `.js` extension Vercel's deployed runtime requires**
- **Found during:** Task 2/3, after the push fixed the 404 but every `/api/*` route still returned `500 FUNCTION_INVOCATION_FAILED`
- **Issue:** Round 1 — Vercel's runtime log: `Error [ERR_MODULE_NOT_FOUND]: Cannot find module '/var/task/api/_lib/db' imported from /var/task/api/drafts/[id].js`. The 04.1-03-PLAN.md "extensionless-import convention for `api/**`" was reasoned only against the local esbuild/Vitest toolchain, which does resolve extensionless specifiers — Vercel's deployed Function runtime instead runs the compiled `.js` output through Node's native ESM loader, which does not. Round 2 — after fixing only non-test files directly under `api/`, the very next redeploy hit a second, different `ERR_MODULE_NOT_FOUND` for `src/db/schema/index.ts` importing `./users` (no extension), proving `src/**` was not already `.js`-suffixed as assumed.
- **Fix:** Round 1: added `.js` to every relative import in 15 non-test files under `api/`. Round 2: swept ALL of `src/**/*.ts` and `api/**/*.ts` (including test files) in one pass, appending `.js` to every relative import missing it; confirmed via grep that zero extensionless relative imports remain in either tree.
- **Files modified:** 17 files (round 1) + 37 files (round 2) — see Files Created/Modified above
- **Verification:** `npm run typecheck` (0 errors) and `npm test` (781/781 passing) after each round; live curl confirmed the fix — `GET /api/drafts/1` returns `401 {"error":"missing_init_data"}` instead of `500`.
- **Committed in:** `964447c` (round 1), `ffa0d13` (round 2)
