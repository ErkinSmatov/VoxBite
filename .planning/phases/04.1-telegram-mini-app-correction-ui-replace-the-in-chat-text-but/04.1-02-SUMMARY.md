# Phase 04.1 Plan 02: Replace chat correction card with a Mini App Open button Summary

Replaced the Phase 4 `DraftCardRenderer` port (which rewrote the ack message into a full
text correction card with a `crc:` callback keyboard) with a new `OpenCorrectionRenderer`
port that structurally can only ever emit a Telegram `web_app` button addressed at the
draft's id — making the phase 04.1 Mini App reachable for the first time, while the chat
message itself now carries zero component/candidate/nutrient data (D-02/D-03).

## What Was Built

**Task 1 — `MINI_APP_BASE_URL` required env var:**
- `src/config/env.ts`: added `MINI_APP_BASE_URL` to `REQUIRED_ENV_KEYS` and `AppEnv` — the
  bot now refuses to start without it, since after this phase there is no chat-based
  fallback correction UI.
- `.env.example`: added a detailed, owner-facing Russian comment block (what the value is,
  the exact expected shape, that plan 13 deploys the real Vercel URL, restart reminder) plus
  a syntactically valid placeholder (`https://REPLACE-ME.vercel.app`) so `dotenv-safe`'s
  `allowEmptyValues: false` doesn't block local dev before plan 13 ships.
- `src/config/env.test.ts`: updated fixtures across every test case that constructs a valid
  env, and added a new dedicated test asserting `loadEnv()` throws naming
  `MINI_APP_BASE_URL` when it alone is unset.

**Task 2 — `OpenCorrectionRenderer` port + `mini-app-button-renderer.ts`:**
- `src/application/types.ts`: replaced the `DraftCardRenderer` interface (`renderLevel1`)
  with `OpenCorrectionRenderer.renderOpenButton(draftId: number): RenderedCard` — the new
  port receives ONLY a draft id, never a `DraftComponent[]`, which is a structural guarantee
  (not a convention) that the application layer cannot leak meal data into a chat message
  through this seam.
- `src/bot/formatting/pipeline-copy.ts`: added `analysisReady` — the new status line
  ("Разбор готов. Открой, чтобы проверить и сохранить:") that replaces the ack once analysis
  finishes.
- New `src/bot/telegram/mini-app-button-renderer.ts`: `createMiniAppButtonRenderer(baseUrl)`
  builds a grammY `InlineKeyboard().webApp(...)` button whose url is
  `${baseUrl-with-trailing-slashes-stripped}/?draftId=${draftId}`. This is the only file in
  the codebase (besides its test) that imports grammY's `InlineKeyboard` for this purpose —
  `src/application/` still imports zero grammY types.
- `src/application/voice-pipeline.ts`: `PipelineDeps.cardRenderer` renamed to `openRenderer`;
  the single call site now reads `deps.openRenderer.renderOpenButton(draftId)`. The
  "nothing below may overwrite a delivered card with an error" discipline is unchanged.
- Deleted `src/bot/telegram/draft-card-renderer.ts` and its test (the Phase 4 chat-card
  renderer). Its dependents (`correction-card.ts`, `correction-keyboards.ts`) still have
  other callers (`src/bot/handlers/correction.ts`) and were intentionally left in place —
  that removal belongs to plan 11.
- New `src/bot/telegram/mini-app-button-renderer.test.ts`: 4 assertions covering the
  returned text, the `web_app.url` shape (including the trailing-slash-stripping case), and
  that the serialized card contains no component/candidate/nutrient-shaped data.

**Task 3 — wired `miniAppBaseUrl` through the composition root, rewrote the tripwire:**
- `src/bot/pipeline-wiring.ts`: `MealWiringDeps` gained `miniAppBaseUrl: string`;
  `buildMealHandlerDeps` now constructs `createMiniAppButtonRenderer(w.miniAppBaseUrl)`
  instead of `createDraftCardRenderer()`.
- `src/bot/bot.ts`: `BotDeps` gained `miniAppBaseUrl: string` (same "resolved from env by
  index.ts" doc-comment style as `sttModel`), passed into `buildMealHandlerDeps`.
- `src/bot/index.ts`: passes `miniAppBaseUrl: env.MINI_APP_BASE_URL` into `createBot({...})`.
- Rewrote `src/bot/entry-point-reachability.test.ts` (renamed its own describe block to
  "entry-point reachability (04.1-02)"): it now drives `processMeal` for BOTH voice and text
  input through `buildMealHandlerDeps` (still sourcing the renderer from the composition
  root, never a direct `createMiniAppButtonRenderer` import) and asserts:
  - exactly one `editMessage` call,
  - its `replyMarkup` is a non-undefined inline keyboard with exactly one button,
  - that button carries a `web_app` field (not `callback_data`),
  - `web_app.url` contains `draftId=<the id saveDraft actually returned>`,
  - the message `text` contains none of the fixture's component name, candidate
    description, or numeric gram/kcal values (the automated enforcement of D-03).
  All `parseCrc`/`crc:` assertions from the retired chat flow were removed.
- `src/bot/pipeline-wiring.test.ts` and `src/bot/bot.wiring.runtime.test.ts` updated for the
  new required field.
