<objective>
Add the three endpoints behind the candidate picker and the grams control: swap the matched FDC
candidate, nudge grams by the ±10 g step, and apply a typed gram value.

Purpose: CORRECT-03 and CORRECT-04, re-discharged through the Mini App. Each endpoint is a thin
translation of an existing, already-tested `src/application/corrections.ts` function into HTTP —
no correction logic is written here.

**The one thing that is easy to get wrong and must not be:** when the draft being corrected has
already been saved to the diary (`status === 'confirmed'`), the saved diary row must be recomputed
after the mutation. That guard is exactly the defect (04-UAT.md rounds 3-4 / CR-02) that caused
this whole phase to exist. Porting these operations to HTTP without carrying the guard across
would reintroduce it in a new place.
Output: three endpoints plus three test files.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| public internet -> mutation endpoints | Untrusted JSON body reaching a write path |
| draft row -> saved `diary` row | A mutation on a confirmed draft must propagate, or the diary silently lies |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-04.1-18 | Tampering | request bodies | mitigate | `zod` `safeParse` schema on every endpoint before any application call; non-integer / negative / missing indices produce 400 and no write (V5 Input Validation) |
| T-04.1-19 | Tampering | client-chosen gram delta | mitigate | `adjust-grams` accepts only `direction: 'up'|'down'` and derives the magnitude from `GRAM_STEP`; a `delta` field is rejected outright |
| T-04.1-20 | Tampering / Repudiation | diary desync after correcting a saved entry | mitigate | Every mutation endpoint carries the `status === 'confirmed' -> recomputeSavedEntry` guard ported from `correction.ts`, each with a dedicated test and a deliberate-break check. This is the CR-02 regression class |
| T-04.1-21 | Elevation of Privilege | mutating another user's draft | mitigate | `swapCandidate`/`adjustGrams`/`applyTypedGrams` are all `(draftId, userId)`-scoped internally; `userId` comes only from `requireUser` |
| T-04.1-22 | Information Disclosure | logs / error bodies | mitigate | `logApiError(operation, draftId, reason)` only; greps forbid echoing the body or raw gram text |
</threat_model>
