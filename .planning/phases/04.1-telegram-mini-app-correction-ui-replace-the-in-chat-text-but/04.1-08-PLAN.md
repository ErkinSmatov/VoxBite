<objective>
Build the Mini App's shell: the Telegram WebView bridge, the authenticated API client, the shared
types and Russian copy, the theme-driven stylesheet, and the single screen with its loading,
error and loaded states.

Purpose: this is the frame everything else in the UI hangs on. It also settles the three things a
Telegram Mini App gets wrong most often — reading `initData` (not `initDataUnsafe`) for auth,
consuming Telegram's injected theme variables instead of a hardcoded palette, and calling
`ready()`/`expand()` before first paint.
Output: a working screen that loads a real draft and renders its components as plain rows;
interactive controls arrive in plans 09 and 10.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Telegram WebView -> browser JS | Everything in the SPA is client-controlled and untrusted by the server |
| SPA -> `/api/*` | The `initData` string is the only credential transmitted |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-04.1-34 | Spoofing | `initDataUnsafe` misuse | mitigate | `api-client.ts` sends only the raw `initData` string; greps forbid `initDataUnsafe`, `userId`, `telegramId` anywhere in the client's request path |
| T-04.1-35 | Information Disclosure | distinguishing "expired" from "not yours" | mitigate | 401/403/404/410 all render one shared copy constant, defined once and referenced twice, with the reason written down next to it |
| T-04.1-36 | Tampering | client-side nutrient recomputation | mitigate | `updateFromResponse` re-renders from the API payload only; acceptance criteria greps every `.tsx` for `grams`-times-nutrient arithmetic and requires zero matches (CALC-01) |
| T-04.1-37 | Information Disclosure | health data cached by the WebView | accept | Data is rendered in memory only; nothing is written to `localStorage`/`sessionStorage` or a service worker in this phase. Do not add client-side persistence |
| T-04.1-38 | Denial of Service | retry loop on a failing API | mitigate | Retry is an explicit user tap on `Обновить`, never an automatic timer |
</threat_model>
