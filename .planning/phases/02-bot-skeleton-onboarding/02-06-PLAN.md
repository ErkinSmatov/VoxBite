<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| `/start` from an already-onboarded user -> stored profile | A careless implementation would restart the questionnaire and overwrite a good profile |
| Redo-onboarding callback -> conversation entry | Another client-supplied `callback_data` value |
| Checklist instructions -> owner's terminal and `.env` | Instructions that are wrong or lossy send the owner to unsafe workarounds |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-02-21 | Tampering (data loss) | `/start` on an onboarded user | mitigate | The handler reads `onboardedAt` and branches to a read-only summary; entering the conversation requires an explicit button press, and re-onboarding overwrites through the same idempotent upsert rather than deleting anything |
| T-02-22 | Tampering | Redo-onboarding callback value | mitigate | The handler matches an exported constant exactly; any other callback data falls through to grammY's default no-op rather than entering a flow |
| T-02-23 | Elevation of Privilege | New handlers registered ahead of the allowlist gate | mitigate | The automated check in Task 1 asserts the registration order (allowlist -> session -> conversations -> handlers) and fails the task if a handler is added before the gate |
| T-02-24 | Information Disclosure | Checklist telling the owner to paste logs or tokens | mitigate | The checklist instructs the owner to copy only the numeric `telegram_id` out of the log, and explicitly warns that anything resembling the token must not be shared |
</threat_model>
