# Ручная проверка Phase 2 — бот-скелет + онбординг

> Этот документ — для тебя, если ты никогда раньше не запускал backend-процесс.
> Каждый шаг говорит: какую команду ввести, где её вводить, что должно
> появиться на экране, и что делать, если появилось что-то другое.
>
> Термины по ходу: "терминал" — программа для ввода текстовых команд
> (на Mac — приложение Terminal или iTerm); "процесс" — запущенная
> программа, которая работает, пока не остановишь её (Ctrl+C) или не
> закроешь терминал; "long polling" — способ, которым бот сам спрашивает
> Telegram "есть новые сообщения?" вместо того, чтобы Telegram стучался к
> нему — из-за этого **только один запущенный процесс бота может держать
> соединение с одним токеном одновременно**.

## Раздел 0 — Первый запуск (обязательно пройти первым)

Файл `BETA_ALLOWLIST` в `.env` сейчас **пустой** — это специально. Пока он
пустой, бот отказывает вообще всем, включая тебя самого. Это правильное
поведение "закрыто по умолчанию" (D-04): бот в закрытой бете. Ниже — как
узнать свой собственный `telegram_id` и открыть себе доступ.

- [ ] **Шаг 1.** Открой терминал в корне проекта (там, где лежит `package.json`)
      и введи:
      ```
      npm run bot
      ```
      Ожидаемый результат: строка вида
      `Бот запущен: @<имя_твоего_бота>. Останови его сочетанием Ctrl+C.`
      плюс перед этим — строка про пустой `BETA_ALLOWLIST` с пояснением, что
      это ожидаемо при первом запуске.

      Если вместо этого видишь что-то про `TELEGRAM_BOT_TOKEN` — значит в
      файле `.env` в корне проекта строка `TELEGRAM_BOT_TOKEN=` пустая или
      её нет. Открой `.env`, впиши туда токен, который тебе прислал
      @BotFather в Telegram (см. Plan 01), сохрани файл и повтори шаг 1.

- [ ] **Шаг 2.** Не закрывая терминал, открой Telegram, найди своего бота по
      его `@username` (та же строка, что появилась на шаге 1 после
      `Бот запущен: @`) и нажми кнопку "Start" внизу экрана, либо сам
      отправь сообщение `/start`.

      Ожидаемый результат в Telegram: бот отвечает
      `Бот сейчас в закрытой бете. Попроси доступ у владельца бота.`
      Это ожидаемо — ты ещё не в списке допущенных.

- [ ] **Шаг 3.** Посмотри на терминал (тот, где запущен `npm run bot`). Там
      должна появиться строка вида:
      ```
      отказ: telegram_id=123456789, @твой_username
      ```
      Число после `telegram_id=` — это твой личный Telegram ID. Скопируй
      только это число (никакие другие символы из строки копировать не
      нужно).

- [ ] **Шаг 4.** Останови бота: кликни в терминал и нажми `Ctrl+C`. Дождись
      строки `Останавливаю бота...` — это значит процесс завершился
      корректно.

      Открой файл `.env` в корне проекта в любом текстовом редакторе, найди
      строку `BETA_ALLOWLIST=` и допиши туда своё число без пробелов и без
      кавычек, например:
      ```
      BETA_ALLOWLIST=123456789
      ```
      Сохрани файл.

- [ ] **Шаг 5.** Запусти бота снова:
      ```
      npm run bot
      ```
      В Telegram отправь боту `/whoami`. Ожидаемый результат: бот отвечает
      строкой вида `Твой telegram_id: 123456789 — впиши его в BETA_ALLOWLIST
      в файле .env и перезапусти бота.` — число должно совпасть с тем, что
      ты вписал в `.env`.

      Если бот всё ещё отвечает про закрытую бету — значит число в `.env`
      не совпадает с числом из строки `отказ:` на шаге 3, либо ты забыл
      сохранить `.env`, либо забыл перезапустить бота после сохранения.
      Проверь число ещё раз и повтори шаг 5.

- [ ] **Шаг 6 (не обязателен для первого запуска, но пригодится).** Чтобы
      добавить друга: попроси его нажать Start у бота, найди его строку
      `отказ: telegram_id=...` в своём терминале, и допиши его число через
      запятую в `.env`:
      ```
      BETA_ALLOWLIST=123456789,987654321
      ```
      Сохрани файл и перезапусти бота (`Ctrl+C`, затем снова `npm run bot`).

## Раздел 1 — Критерий 1: `/start` проводит через все 7 вопросов

Требование: ONBOARD-01. Отправь боту `/start`.

- [ ] Вопросы приходят по одному, а не все сразу: пол → возраст → рост →
      вес → уровень активности → цель → (скорость, если цель не
      "поддержание") → часовой пояс.
- [ ] Пол, активность, цель и часовой пояс — это кнопки под сообщением
      (нажимаешь, не печатаешь).
- [ ] Возраст, рост, вес — это вопросы, на которые нужно напечатать число
      текстом.
- [ ] На вопросе про возраст специально напиши `abc` (не число). Ожидаемый
      результат: бот НЕ падает и не показывает никакой технической ошибки —
      он переспрашивает по-русски и в сообщении есть пример числа (например
      "например 29"). Введи корректное число и продолжай.
- [ ] После ответа на все вопросы бот присылает сообщение с рассчитанными
      калориями и БЖУ (белки/жиры/углеводы).

## Раздел 2 — Критерий 2: скорость похудения/набора не больше 1 кг/мес

Требование: ONBOARD-02. Пройди `/start` заново (или из середины опроса
дойди до вопроса про цель) и выбери цель "снижение веса" или "набор веса"
(не "поддержание").

- [ ] На вопросе про скорость изменения веса — ровно четыре кнопки:
      `0.25 кг/мес`, `0.5 кг/мес`, `0.75 кг/мес`, `1 кг/мес`.
- [ ] Кнопки со значением больше `1 кг/мес` нет.
- [ ] Нет способа напечатать число самому в этом вопросе — только кнопки.

## Раздел 3 — Критерий 3: подтверждение и "Изменить" (ONBOARD-05)

Требование: ONBOARD-05. Дойди до экрана с рассчитанными целями (конец
опроса).

- [ ] На экране с целями — две кнопки: "Всё верно" и "Изменить".
- [ ] Нажми "Изменить". Ожидаемый результат: бот пишет, что начинает заново
      и предыдущие ответы не сохранены, и весь опрос начинается с первого
      вопроса (пол) — заново.
- [ ] Пройди опрос второй раз и на этот раз нажми "Всё верно". Ожидаемый
      результат: бот отвечает `Готово! Твои цели рассчитаны и сохранены.`
- [ ] Отправь `/start` ещё раз (третий заход). Ожидаемый результат: опрос
      **не** начинается заново — бот сразу присылает сообщение
      "С возвращением! Вот твои текущие цели:" с теми же числами, что были
      сохранены, и кнопкой "Пройти анкету заново". Это доказывает, что
      "Изменить" не затирает уже сохранённый профиль просто так — новый
      опрос запускается только явным нажатием кнопки.

## Раздел 4 — Критерий 4: дисклеймер виден до подтверждения (ONBOARD-06)

Требование: ONBOARD-06. На экране с рассчитанными целями (тот же экран, что
в Разделе 3, до нажатия любой кнопки):

- [ ] В этом же сообщении, под цифрами калорий и БЖУ, есть текст с

      диетологом.
- [ ] Этот текст виден **до** того, как ты нажал "Всё верно" — то есть его
      нельзя случайно пропустить.

> Текст дисклеймера в разделе выше утверждён владельцем без изменений

## Раздел 5 — Устойчивость (что бот не должен ронять)

- [ ] **Два процесса одновременно (409 Conflict).** Оставь `npm run bot`
      запущенным в одном терминале. Открой **второй** терминал (тоже в
      корне проекта) и там тоже введи `npm run bot`. Ожидаемый результат во
      втором терминале:
      ```
      Похоже, бот уже запущен в другом терминале — закрой его и запусти снова.
      Только один процесс может использовать один токен одновременно.
      ```
      и процесс сам завершается — это не "зависание", это ожидаемое
      поведение. Не должно быть ничего похожего на длинный текст ошибки
      (stack trace) и не должно быть видно значения токена. Останови
      второй процесс (если он ещё жив — `Ctrl+C`) перед тем, как продолжать.

- [ ] **Перезапуск бота посреди опроса (Pitfall 2).** С запущенным ботом
      отправь `/start`, ответь на первые три вопроса (пол, возраст, рост).
      Не отвечая на четвёртый вопрос — переключись в терминал и нажми
      `Ctrl+C`. Запусти бота снова: `npm run bot`. Вернись в Telegram и
      продолжи отвечать на оставшиеся вопросы с того места, где
      остановился. Ожидаемый результат: бот **помнит**, что ты уже ответил
      на первые три вопроса, и не переспрашивает их заново. Доведи опрос до
      конца и нажми "Всё верно".

      Затем открой Supabase (сайт supabase.com → твой проект → в левом меню
      Table Editor → таблица `users`) и проверь: там должна быть **ровно
      одна** строка с твоим `telegram_id`, без дублей и без строк с
      наполовину пустыми полями.

- [ ] **Нет интернета.** Отключи Wi-Fi (или выключи интернет любым другим
      способом), затем запусти `npm run bot`. Ожидаемый результат: бот
      печатает по-русски что-то вроде "Не удалось связаться с Telegram —
      проверь интернет-соединение", а не длинный текст ошибки. Включи
      интернет обратно и убедись, что `npm run bot` снова запускается
      нормально.

## Раздел 6 — Что делать, если что-то не так

| Симптом | Вероятная причина | Что делать |
|---|---|---|
| `npm run bot` пишет что-то про `TELEGRAM_BOT_TOKEN` и сразу завершается | В `.env` пустой или неверный токен | Открой `.env`, проверь строку `TELEGRAM_BOT_TOKEN=`, возьми токен заново у @BotFather |
| Бот всегда отвечает "закрытая бета", даже после того как ты вписал число в `BETA_ALLOWLIST` | Число не совпадает, `.env` не сохранён, или бота не перезапустили | Сверь число из строки `отказ: telegram_id=...` в терминале с числом в `.env` посимвольно, сохрани файл, `Ctrl+C` и снова `npm run bot` |
| Второй `npm run bot` в другом терминале выдаёт ошибку про 409 | Это ожидаемо — работает только один процесс бота одновременно | Останови один из двух процессов (`Ctrl+C`) — не запускай два `npm run bot` одновременно вне этой проверки |
| Опрос при перезапуске бота "забывает" уже данные ответы | Незавершённый опрос теряет прогресс | Это баг — сообщи разработчику; ожидаемое поведение описано в Разделе 5 |
| Бот падает / показывает длинный текст с `at ...` (stack trace) | Необработанная ошибка | Скопируй текст ошибки **без** значений, похожих на токен или на длинную строку с `postgres://`, и сообщи разработчику |
| На экране с целями нет кнопок "Всё верно"/"Изменить" | Скорее всего это баг в коде, а не в настройке | Сообщи разработчику, приложи скриншот |
