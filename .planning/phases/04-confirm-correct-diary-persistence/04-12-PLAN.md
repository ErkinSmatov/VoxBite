<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Telegram → bot (callback_data) | The `crc:` payload this plan now actually emits comes back as attacker-controllable text |
| pipeline → Telegram (card body) | FDC descriptions and LLM component names are echoed into a message |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-04-06 | Tampering | `parseCrc` on inbound callback_data | mitigate (existing, 04-09) | Anchored `CRC_PATTERN` + action allowlist; this plan adds no new parse path and must not introduce a `split(':')` shortcut |
| T-04-01 | Elevation | draftId now visible in every emitted button | mitigate (existing, 04-09) | `readDraft(db, draftId, user.id)` is user-scoped; guessing another user's draftId yields the `notYours` copy, byte-identical to `expired` |
| T-04-40 | Information disclosure | new `renderLevel1` output | mitigate | Keyboard payloads go through `encodeCrc` only — integers and short ASCII action tokens, never a component name or transcript (64-byte cap + T-04-07 logging rule) |
| T-04-12 | Denial of service | card body rendered as plain text | accept (existing, T-03-12) | No `parse_mode` is set on the edit call, so an FDC description containing `_`/`*` cannot break rendering — Task 1 must not add `parse_mode` |
</threat_model>
