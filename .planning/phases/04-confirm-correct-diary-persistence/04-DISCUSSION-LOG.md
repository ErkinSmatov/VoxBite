## Форма карточки и клавиатуры

### Q1 — структура карточки коррекции

| Option | Description | Selected |
|--------|-------------|----------|
| Два уровня: список → экран компонента | Главная карточка со списком + по кнопке на компонент; тап открывает экран правки в том же сообщении. Число кнопок не растёт с числом ингредиентов. | ✓ |
| Одна плоская карточка | Ряд `▾ −10 +10 ✕` на каждый компонент. Меньше тапов, но 5 компонентов = 20 кнопок. | |
| Три уровня: Подтвердить / Поправить | Две кнопки на главной, меню выбора компонента вторым уровнем. Чистейший экран, самый длинный путь до правки. | |

**Notes:** Решающий аргумент — бешбармак реально даёт 4-5 компонентов; при плоской раскладке клавиатура занимает пол-экрана телефона. → D-01

### Q2 — как показывать 3 кандидата FDC

| Option | Description | Selected |
|--------|-------------|----------|
| Описания в тексте, кнопки «1 / 2 / 3» | Полные описания дословно в теле сообщения с галочкой у текущего, три узкие кнопки-цифры под ними. | ✓ |
| Каждый кандидат — кнопка с описанием | Три широкие кнопки. Проще попасть пальцем, но Telegram обрежет длинное описание. | |
| Описания в тексте + ккал каждого | Как вариант 1, плюс ккал/100 г рядом с каждым кандидатом. | |

**Notes:** Различающая информация в описаниях FDC стоит в конце строки (raw / cooked, roasted) — ровно там, где Telegram ставит многоточие на кнопке. → D-02

### Q3 — показывать ли КБЖУ до подтверждения (ревизия Phase 3 D-20)

| Option | Description | Selected |
|--------|-------------|----------|
| Да, живой предварительный итог | Одна строка `≈ 620 ккал · Б 45 · Ж 28 · У 44`, пересчёт при каждой правке, со знаком ≈ и пометкой «пока не сохранено». | ✓ |
| Нет, только после подтверждения | D-20 остаётся как есть; правка идёт вслепую. | |
| Только на экране компонента | Главный список без чисел, вклад отдельного ингредиента виден при его правке. | |

**Notes:** Явная ревизия решения прошлой фазы. К решению привязано жёсткое ограничение: превью и финал считает одна и та же чистая функция (прецедент — `isWeakMatch`). → D-03

### Q4 — как развести текстовый ввод коррекции и новое блюдо

| Option | Description | Selected |
|--------|-------------|----------|
| Флаг ожидания в черновике + Reply-to | `awaiting_input` в строке черновика (Postgres, переживает рестарт); следующий текст юзера идёт в коррекцию, а не в платный пайплайн. Гаснет по тайм-ауту или кнопке Отмена. | ✓ |
| ForceReply от Telegram | Отдельное сообщение с force_reply, ответ узнаётся по reply_to_message_id. Ломает D-13 и легко промахнуться мимо reply. | |
| Только кнопки, без текстового ввода | Частичный отказ от CORRECT-04 и полный — от CORRECT-06. | |

**Notes:** Проблема поднята Claude как риск: сейчас любое текстовое сообщение стоит денег (VOICE-04). → D-04

## Подтверждение, сохранение, правка сохранённого

### Q1 — что на экране после подтверждения

| Option | Description | Selected |
|--------|-------------|----------|
| Та же карточка становится записью дневника | Перерисовка того же сообщения: финальные КБЖУ, день сохранения, кнопки `✎ Поправить` / `🗑 Удалить`; правка открывает тот же двухуровневый экран. | ✓ |
| Карточка замораживается, правка через дневник | Кнопки снимаются; править только из списка дневника — но дневник это DIARY-02, т.е. фаза 5. CORRECT-08 стало бы нечем проверить. | |
| Карточка замораживается + команда /last | Отдельная команда достаёт последние записи со своими кнопками. Больше кода. | |

**Notes:** → D-05

### Q2 — где живёт состав сохранённой записи

| Option | Description | Selected |
|--------|-------------|----------|
| Черновик — рабочая копия, `diary` — снимок итогов | Черновик → `status='confirmed'`, живёт вечно; в `diary` строка с итогами и ссылкой на черновик. Один код коррекции до и после сохранения, ноль новых таблиц. | ✓ |
| Копия состава в `diary.components` | Своя jsonb-копия у записи дневника; черновики можно чистить свободно, но два контейнера = два пути коррекции. | |
| Отдельная таблица `diary_items` | Нормальный реляционный вид, полезен для будущей аналитики — но это миграция и лишний слой ради фичи, которой нет в v1. | |

**Notes:** → D-06. Следствие: чистка черновиков не имеет права трогать confirmed-строки.

### Q3 — за какой день записывать (DIARY-01)

| Option | Description | Selected |
|--------|-------------|----------|
| День по моменту сообщения, заморожен | `local_date` считается от времени исходного сообщения в таймзоне юзера и не меняется ни при подтверждении, ни при правке. | ✓ |
| День по моменту подтверждения | Проще в коде, но ужин в 23:50 уезжает в следующий день и портит оба дня в сводке. | |
| По сообщению + кнопка «вчера/сегодня» | Плюс ручной перенос дня. Больше кнопок и ещё один случай в тестах. | |

**Notes:** → D-07; ручной переключатель дня ушёл в Deferred.

### Q4 — насколько окончательно удаление

| Option | Description | Selected |
|--------|-------------|----------|
| Подтверждение + жёсткое удаление | `🗑 Удалить` → «Удалить запись? Да/Нет» → DELETE строки `diary`, черновик → abandoned. | ✓ |
| Мягкое удаление (`deleted_at`) | Можно отменить, но каждый запрос дневника обязан помнить про фильтр — забыл один раз и числа врут. | |
| Без подтверждения, сразу | Кнопка живёт рядом с «Поправить» в истории чата; случайный тап через неделю убьёт данные. | |

**Notes:** → D-08

## Честность чисел и вырожденные случаи

### Q1 — частично известный нутриент (CALC-02)

| Option | Description | Selected |
|--------|-------------|----------|
| `≥ 12 г (у 1 из 5 нет данных)` | Сумма по известным со знаком «не менее» и явным счётчиком неучтённых. Правило для любого нутриента, не только сахара. | ✓ |
| «нет данных» на весь итог | Максимально строго, но на реальных блюдах сахар почти всегда окажется «нет данных» — фича станет бесполезной. | |
| Обычная сумма + сноска мелким текстом | Читается проще всего, но число выглядит полным итогом — тот самый ложный комфорт, о котором предупреждает TECH_SPEC §5.8. | |

**Notes:** → D-09

### Q2 — компонент без единого кандидата FDC

| Option | Description | Selected |
|--------|-------------|----------|
| Блокировать подтверждение до решения | «Подтвердить» отказывает, называет компонент и предлагает убрать его или описать иначе. | ✓ |
| Позволить, но пометить итог неполным | Компонент входит с нулевым вкладом, все итоги идут со знаком «≥». В дневник ложится заниженное число. | |
| Автоматически выбросить компонент | Противоречит Phase 3 D-21 — калории исчезают из блюда без объяснения. | |

**Notes:** Уже: слабое совпадение подтверждается свободно (D-21 в силе), блокирует только полное отсутствие матча. → D-10

### Q3 — протухшие черновики

| Option | Description | Selected |
|--------|-------------|----------|
| Срок жизни черновика 24 ч | Старше суток и всё ещё draft — кнопки не работают, бот отвечает «разбор устарел, отправь заново», клавиатура снимается. | ✓ |
| Без срока годности | Меньше кода, но старые карточки остаются «живыми минами» в истории чата. | |
| Срок 24 ч + автоочистка старых строк | Плюс фоновое удаление брошенных черновиков — но нужен планировщик, которого в этой фазе нет. | |

**Notes:** → D-11; фоновая очистка ушла в Deferred (транскрипты — чувствительные данные, откладывать бесконечно нельзя).

### Q4 — удалены все компоненты (CORRECT-05)

| Option | Description | Selected |
|--------|-------------|----------|
| Пустое состояние + «Добавить» / «Отменить разбор» | «Компонентов не осталось», `✅ Подтвердить` исчезает; пустая запись в дневник попасть не может. | ✓ |
| Запретить удалять последний | Тупиковый ответ вместо действия. | |
| Автоматически отменить разбор | Один лишний тап — и разбор потерян без возврата. | |

**Notes:** → D-12
