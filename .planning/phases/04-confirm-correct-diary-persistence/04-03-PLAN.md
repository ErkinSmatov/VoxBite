Create `src/bot/telegram/safe-edit.ts`.

Export two functions with structurally typed ctx parameters, exactly mirroring `ack.ts`'s
approach of NOT importing grammY's `Context`:
- `safeEditMessageText(ctx: EditableTextCtx, text: string, other?: unknown): Promise<void>`
  where `EditableTextCtx` is an exported interface declaring
  `editMessageText: (text: string, other?: never) => Promise<unknown>` (loosened as needed so
  a grammY `Context` structurally satisfies it — verify with `npx tsc --noEmit` after wiring,
  and if grammY's overloads fight the narrow signature, widen the parameter types rather than
  importing `Context`).
- `safeEditMessageReplyMarkup(ctx: EditableMarkupCtx, other?: unknown): Promise<void>` over
  `editMessageReplyMarkup`.

Both catch, inspect, and:
- swallow ONLY when the error is a `GrammyError` (imported as a value from `grammy` for the
  `instanceof` check — this is the one grammY import allowed in this file, same as the type
  import already present elsewhere under `src/bot/telegram/`) AND its `description` contains
  the substring `'message is not modified'`;
- rethrow everything else unchanged. No blanket `catch {}`. No logging — a no-op edit is
  normal user behaviour, not an incident, exactly as `ack.ts` argues for stale callbacks.

The file's header comment must state: which error is swallowed and its literal Telegram text;
the two mainstream user actions that produce it in this phase (tapping `← Назад` onto an
unchanged level-1 screen, re-selecting the already-chosen candidate — 04-RESEARCH.md Pitfall

which is a real bug worth surfacing.

Create `src/bot/telegram/safe-edit.test.ts` covering every case in `<behavior>`, following

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Telegram API errors → bot error handler | A swallowed error class hides real failures; an unswallowed normal one reaches the user as a fake incident |
| Bot copy → user | Copy that leaks internal state (ids, existence of another user's draft) is an information-disclosure channel |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-04-17 | Information Disclosure | `correctionCopy.notYours` | mitigate | The response to "this draft is not yours" is byte-identical to the expired-draft response, so a tapping user cannot distinguish "id does not exist" from "id belongs to someone else"; asserted by a unit test |
| T-04-18 | Denial of Service (self-inflicted) | `safeEditMessageText` | mitigate | Only `GrammyError` with description containing 'message is not modified' is swallowed; `message to edit not found` and transport errors still propagate to `bot.catch()`, so a genuinely broken redraw stays visible |
| T-04-19 | Information Disclosure | copy strings | mitigate | No copy entry interpolates an internal id, error string, or transcript; only component names the user themselves supplied |
| T-04-20 | Tampering | plain-text rendering | mitigate | All strings sent with no `parse_mode`; test asserts no `*`/`_` in copy so an FDC description containing markup cannot break rendering (Phase 3 `result-card.ts` invariant preserved) |
</threat_model>
