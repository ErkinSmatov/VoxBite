# Requirements: VoxBite

**Defined:** 2026-08-10
**Core Value:** Точность распознавания блюда и подсчёта КБЖУ — это должно
работать надёжно, даже если оплата, лимиты и напоминания на старте
отсутствуют.

## v1 Requirements

Requirements for initial closed-beta release (владелец + друзья, без оплаты).

### Onboarding

- [x] **ONBOARD-01**: Пользователь проходит онбординг: пол, возраст, рост,
      текущий вес, уровень активности, цель (набор/снижение веса/поддержание
      и биохакинг), часовой пояс
- [ ] **ONBOARD-02**: При цели набора/снижения веса пользователь задаёт
      желаемый темп, ограниченный сверху 1 кг/месяц
- [x] **ONBOARD-03**: Бот считает целевые калории по формуле
      Миффлина-Сан Жеора + TDEE + ограничение темпа, с нижним безопасным
      порогом калорийности (см. TECH_SPEC.md §6.3)
- [ ] **ONBOARD-04**: Бот считает целевые БЖУ (граммы) на основе целевых
      калорий и пресетов по цели
- [ ] **ONBOARD-05**: Пользователь видит рассчитанные цели и может
      подтвердить их или заново пройти онбординг для изменения вводных
- [ ] **ONBOARD-06**: На онбординге пользователь видит дисклеймер, что бот
      не медицинское изделие и не заменяет консультацию врача/диетолога

### Voice & Text Input

- [ ] **VOICE-01**: Пользователь может отправить боту голосовое сообщение с
      описанием съеденного
- [ ] **VOICE-02**: Бот мгновенно подтверждает получение сообщения, пока идёт
      обработка ("Секунду, разбираю")
- [ ] **VOICE-03**: Голосовое сообщение переводится в текст через STT
      (русский/казахский)
- [ ] **VOICE-04**: Пользователь может вместо голосового отправить текстовое
      описание съеденного — обрабатывается той же цепочкой, что и
      расшифрованный голос

### Dish Decomposition

- [ ] **DECOMP-01**: LLM раскладывает распознанный текст на компоненты
      блюда, каждый — с названием на английском и оценкой граммовки
- [ ] **DECOMP-02**: Простое однокомпонентное блюдо (например, "банан")
      даёт один компонент, а не искусственно раздробленный список
- [ ] **DECOMP-03**: Вывод LLM проходит схемную валидацию (structured
      output + Zod); при невалидном/пустом результате — повтор запроса или
      сообщение пользователю "не смог разобрать, опиши иначе"

### FDC Matching

- [x] **MATCH-01**: Каждый компонент блюда сопоставляется с 3 кандидатами
      из USDA FDC через embedding-based vector search
- [x] **MATCH-02**: Индексируется только USDA FDC Foundation Foods + SR
      Legacy (без Branded Foods)

### Confirm & Correct

- [ ] **CORRECT-01**: Бот показывает пользователю карточку разбора блюда:
      каждый компонент, граммовку, сопоставленную FDC-запись
- [ ] **CORRECT-02**: Пользователь может подтвердить разбор как есть
- [ ] **CORRECT-03**: Пользователь может сменить сопоставленный FDC-вариант
      компонента на одного из 3 кандидатов
- [ ] **CORRECT-04**: Пользователь может скорректировать граммовку
      компонента (кнопки ±10 г или ввод числа)
- [ ] **CORRECT-05**: Пользователь может убрать компонент из разбора
- [ ] **CORRECT-06**: Пользователь может добавить недостающий компонент
      текстом — для него запускается тот же поиск по FDC
- [ ] **CORRECT-07**: Состояние черновика коррекции хранится в базе данных
      (не в памяти процесса) и переживает перезапуск бота
- [ ] **CORRECT-08**: Пользователь может отредактировать или удалить уже
      сохранённую запись дневника той же механикой коррекции

### Calculation

- [ ] **CALC-01**: Итоговые калории/белки/жиры/углеводы/сахар для
      подтверждённой записи считаются математически (граммы × нутриенты
      FDC на 100 г), не через LLM
- [ ] **CALC-02**: Если в сопоставленной FDC-записи нет данных по сахару
      (или другому нутриенту) — бот показывает "нет данных", а не 0 и не
      выдуманное значение

### Diary

- [ ] **DIARY-01**: Подтверждённая запись сохраняется в дневник
      пользователя за текущий день (с учётом часового пояса пользователя)
- [ ] **DIARY-02**: Пользователь может посмотреть дневник за день:
      список записей, итоги против целевых КБЖУ
- [ ] **DIARY-03**: Пользователь может посмотреть простую недельную сводку
      (итоги по дням против целевых КБЖУ)

## v2 Requirements

Deferred to future release. Tracked but not in current roadmap.

### Payments

- **PAY-01**: Пользователь может оформить месячную или годовую подписку
  через локальный эквайер (например, Kaspi Pay)
- **PAY-02**: Доступ к боту ограничен активной подпиской
- **PAY-03**: Лимит голосовых сообщений в месяц зависит от тарифа

### Notifications

- **NOTIF-01**: Бот присылает напоминание занести приём пищи, если
  пользователь давно не писал
- **NOTIF-02**: Бот присылает мотивационные сообщения по расписанию

### Goal Tracking

- **GOAL-01**: Периодическое обновление веса и пересчёт целевых КБЖУ
- **GOAL-02**: Онбординг проверяет беременность/кормление и блокирует
  агрессивный дефицит калорий в этом случае

### Other

- **MEM-01**: Бот запоминает частые персональные коррекции пользователя
  (например, "картофель" почти всегда значит именно этот сорт)
- **SCAN-01**: Сканирование штрихкода продукта (требует USDA FDC Branded
  Foods — вне scope v1)
- **PHOTO-01**: Логирование по фото блюда

## Out of Scope

Explicitly excluded. Documented to prevent scope creep.

| Feature | Reason |
|---------|--------|
| Оплата и подписка | Отдельная фаза после проверки core-цикла на узком кругу — не блокирует проверку главной ценности продукта |
| Напоминания/мотивационные уведомления | Не влияют на точность распознавания/расчёта — ценность продукта проверяется без них |
| Публичный запуск/маркетинг | v1 — закрытая бета (владелец + друзья), не публичный продукт |
| USDA FDC Branded Foods (~2 млн записей) | Не нужны для точности типовых блюд, сильно раздувают объём индексации; также требуются для штрихкод-сканирования, которое тоже вне scope |
| Цветовая индикация "хорошо/плохо" для еды, шейминг-стрики | Исследование показывает, что это подрывает доверие и связано с риском триггерить расстройства пищевого поведения (см. FEATURES.md) — сознательно исключено навсегда, не просто отложено |
| AI-советы/коучинг по питанию | Юридический риск и конфликт с позиционированием "калькулятор, а не коуч" + дисклеймер о том, что бот не медицинское изделие |
| Персональная память коррекций, сканирование штрихкода, фото-логирование, синхронизация с носимыми устройствами | Усложняют реализацию непропорционально ценности на этапе проверки гипотезы; см. v2 |
